# CLAUDE.md: project guide for Claude Code

Loaded at the start of every session. Personal overrides go in `CLAUDE.local.md`.

## Project overview

Planar **3-RRR parallel manipulator** (3 servo-driven legs, triangular platform, 3 DOF: x, y, φ) controlled by IMU tilt or ROS 2. The repository is an engineering project *and* a course, so code and docs must stay consistent and every number in the docs must come from the code.

## Tech stack

| Area | Tech |
|---|---|
| Maths library | Python 3.10+ / numpy, `ros2_ws/src/pm3rrr_core` (**no ROS imports**) |
| Middleware | ROS 2 **Humble**, ament_python / ament_cmake, `ros2_control`, Gazebo **Classic 11**, RViz2 |
| Robot model | xacro → URDF, SRDF; meshes generated by `tools/cad_to_urdf` |
| Desktop physics | MuJoCo (loads the same URDF), `simulation/` |
| Firmware | Arduino C++ (AVR Uno/Nano), `firmware/` |
| CAD | SolidWorks (`hardware/cad`), STL (`hardware/stl`) |

## Architecture (data flow)

```
target_pose → pm3rrr_controller (rate limit → singularity guard → IK) → {joint_states | JTC | serial_bridge → firmware}
```

Single source of truth for the geometry: `ros2_ws/src/pm3rrr_description/config/robot_params.yaml`
→ read by the xacro, `RobotParams.from_yaml`, and mirrored in `firmware/pm3rrr_firmware/config.h`. Tests fail if they disagree.

## Invariants (never break these)

1. **SI units** in code (m, rad, kg, N m). Docs and firmware may use mm/deg, but must say so explicitly.
2. **Zero = home**: every URDF joint is 0 at the home pose (offsets live in the joint origins). `Pm3rrrKinematics.joint_state()` follows this.
3. Working mode **σ = (−1, −1, −1)**, θ = β − α. Do not change it without regenerating the docs and figures.
4. **Every commanded pose passes the guard** (IK ok, servo limits, κ ≤ 10, same assembly mode). Firmware: `type2 > 0.25 && type1 > 0.30`.
5. Generated files are never edited by hand: `meshes/`, `config/inertials.yaml`, `config/pm3rrr.srdf`, `docs/media/**`. Regenerate them with the scripts.
6. `legacy/` stays unchanged (historical record). Fix things in the new code.

## Commands

```bash
python3 -m pytest ros2_ws/src/pm3rrr_core/test                      # maths (23 tests)
PYTHONPATH=tools/cad_to_urdf/_ros_shim python3 -m pytest ros2_ws/src/pm3rrr_description/test
python3 tools/cad_to_urdf/step4_validate_urdf.py                    # URDF ↔ maths loop closure
make -C firmware/test                                               # firmware C++ vs Python
python3 simulation/run_all.py --no-media                            # scenario KPIs
python3 analysis/generate_figures.py                                # lesson figures
cd ros2_ws && colcon build --symlink-install && colcon test         # ROS 2 (Humble)
```

## Conventions

* Code style: `.claude/rules/code-style.md`. Testing: `.claude/rules/testing.md`. ROS interfaces: `.claude/rules/api-conventions.md`.
* Branches: `feature/<topic>`, `fix/<topic>`. Commit messages are imperative ("Add …", "Fix …").
* When you change maths: update the lesson in `docs/learning/`, regenerate the affected figures or GIFs, and update any number quoted in `README.md` or `docs/scenarios/`.
